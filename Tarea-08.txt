Tarea 8: Auditoría Antifraude y Detección de Operaciones Sospechosas (AML) en OmniBank

Código SQL

SELECT transaction_id, amount, tx_type, tx_timestamp,
COALESCE(description,'EXCLUSIÓN OPORTUNAMENTE DETECTADA - SIN MOTIVO DE PAGO') AS descripcion_monitoreada
FROM core.transactions
WHERE
(amount >= 10000.00 AND tx_type IN ('TRANSFER', 'WITHDRAWAL'))
OR
(description ILIKE '%crypto%'
 description ILIKE '%offshore%'
 description ILIKE '%shell%'
 description ILIKE '%casino%'
OR
(NULLIF(TRIM(description), '') IS NULL
AND tx_type != 'DEPOSIT')
ORDER BY amount DESC;

Explicación:

La consulta original generó miles de falsos positivos porque no controlaba correctamente la precedencia de los operadores lógicos. En SQL, el operador AND tiene prioridad sobre OR, por lo que la condición fue evaluada de forma distinta a la intención del negocio. Como resultado, cualquier transacción con description IS NULL era marcada como sospechosa, incluso si se trataba de depósitos normales sin riesgo.
